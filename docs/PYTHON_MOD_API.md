# Python Mod API v2

Поддерживаются два формата модов:

- Пакет-папка `mods/my_mod/` с `mod.json` и Python entry-файлом. Это основной формат для модов с предметами и сущностями.
- Одиночный файл `mods/my_mod.py`. Его ID берётся из имени файла; такой мод подключает тот же SDK, но не может объявить предметы или сущности через manifest.

Игра запускает каждый включённый мод отдельным процессом Python 3 (`python3 -u`; переменная `BARNOCRAFT_PYTHON` позволяет указать другую команду). Дополнительные pip-пакеты не нужны: SDK использует только стандартную библиотеку и доступен как `from barnocraft import Mod`.

Папка модов ищется сначала как `mods/` относительно текущей директории, затем рядом с JAR/каталогом классов игры. Путь можно задать явно системным свойством `-Dbarnocraft.mods=/path/to/mods`.

## Первый мод

```text
mods/hello/
  mod.json
  main.py
```

`mod.json`:

```json
{
  "id": "hello",
  "name": "Hello",
  "version": "1.0.0",
  "api": 2,
  "entry": "main.py",
  "enabled": true
}
```

`main.py`:

```python
from barnocraft import Mod

api = Mod()

@api.on('tick')
def on_tick(snapshot):
    player = snapshot['player']
    if player['health'] < 5:
        api.log('Игроку нужна еда')

api.run()
```

В `id` разрешены строчные латинские буквы, цифры и `_`; первый символ должен быть буквой. `api` должен быть равен `2`. Установите `enabled` в `false`, чтобы пропустить мод при запуске.

## Обмен сообщениями

Игра и мод обмениваются UTF-8 JSON-объектами, по одному на строку. Мод читает события и ответы из stdin; SDK отправляет запросы в stdout. Каждый запрос имеет `id`, `method` и объект `params`; ответ содержит тот же `id` и либо `result`, либо `error`. Не печатайте отладочный текст в stdout: используйте `api.log(...)` или stderr.

`Mod.on(event)` регистрирует обработчик. `api.run()` начинает цикл обмена. Исключение одного обработчика записывается в stderr и не отменяет остальные обработчики события. На событие `load` SDK загружает сохранённое состояние в `api.state`. `api.set_state(**values)` обновляет его и сохраняет в мире; состояние переживает выход и повторную загрузку мира. Событие `unload` отправляется при штатном закрытии мира.

Обработчик `tick` вызывается примерно 10 раз в секунду. Его snapshot имеет вид:

```python
{
    'player': {
        'id': 'player', 'x': 10.5, 'y': 6, 'z': 12.5,
        'health': 20, 'yaw': 0.0, 'item': 'core:stone'
    },
    'time': 0.5,
    'entities': [
        {'id': 'mod:1', 'type': 'pack:wolf', 'x': 14.0, 'y': 6,
         'z': 12.0, 'health': 10, 'owner': '', 'heading': 0.0}
    ]
}
```

`time` циклически меняется от `0` до `1`: ночь — `[0, 0.22)` и `[0.72, 1)`. В `entities` входят сущности модов, зомби (`core:zombie`) и овцы (`core:sheep`). Идентификатор `player` используется как цель игрока.

Другие события: `damage` (`source`, `target`, `amount`), `entity_spawn`, `entity_tamed`, `entity_death`, `entity_use`, `projectile_spawn`, `ui.click` (`id`, `x`, `y`, `button`) и `notice`. Урон игрока или игрока-источника обозначается строкой `player`; прочие источники и цели имеют ID сущности. Зарегистрируйте обработчик до `api.run()`:

```python
@api.on('damage')
def on_damage(event):
    if event['target'] == 'player':
        api.log(f"Получен урон от {event['source']}")
```

## Вызовы API

Все операции доступны через `api.call(method, callback=None, on_error=None, **params)`. Запросы асинхронны; callback получает результат. `on_error` получает объект ошибки. SDK также предоставляет короткие обёртки:

| Метод SDK | JSON-RPC метод | Назначение |
| --- | --- | --- |
| `api.set_state(**values)` | `state.set` | Сохранить состояние мода |
| `api.spawn_entity(type, x, z, callback=None, on_error=None)` | `entity.spawn` | Создать свою сущность рядом с игроком |
| `api.set_goal(id, x, z, stop=1.0, callback=None)` | `entity.goal` | Задать цель перемещения сущности |
| `api.attack_entity(id, target, callback=None)` | `entity.attack` | Атаковать цель в ближнем бою |
| `api.shoot_entity(id, target, callback=None)` | `entity.shoot` | Выстрелить в цель |
| `api.teleport_entity(id, x, z, callback=None)` | `entity.teleport` | Переместить свою сущность |
| `api.remove_entity(id, callback=None)` | `entity.remove` | Удалить свою сущность |
| `api.surface(callback, size=25, step=2, on_error=None)` | `world.surface` | Получить блоки и высоты поверхности вокруг игрока |
| `api.show_image(id, title, pixels, callback=None, on_error=None)` | `ui.image` | Показать пиксельный overlay |
| `api.remove_image(id, callback=None)` | `ui.remove` | Удалить overlay |

Дополнительные методы JSON-RPC: `api.info`, `world.get_block`, `log`. Для `world.get_block` передаются целочисленные `x`, `y`, `z`. Метод `api.log(...)` в Python SDK пишет локально в stderr; для RPC-вызова `log` используйте `api.call('log', message='...')`.

### Ограничения

- ID сущностей, предметов и overlay должны принадлежать namespace мода: например, `wolves:wolf` или `minimap:map`.
- `entity.spawn` принимает только тип, объявленный этим модом; точка должна быть не дальше 64 блоков от игрока. Всего в мире может быть до 64 mod-сущностей.
- `entity.goal` ограничивает координаты границами мира и действует ограниченное время. `entity.teleport` должен оставаться в пределах 32 блоков от игрока.
- `world.surface`: размер 3–33, шаг 1–4 блока, не чаще двух запросов в секунду на мод. Ответ включает начало сетки (`x`, `z`), `step`, `size`, матрицы `blocks` и `heights`.
- `ui.image`: до 4 overlay на мод, матрица до 64×64; цвет ячейки — RGB или RGBA hex без `#`. Overlay ID должен быть namespace мода.
- Клик по overlay отправляет событие `ui.click` с `id`, координатами пикселя `x`/`y` от левого верхнего угла изображения и `button` (`left`/`right`). В игре нажмите `M`, чтобы показать курсор и включить взаимодействие с мини-картой; `M` повторно возвращает обычное управление.
- Сохранённое состояние ограничено 64 KiB. Очереди и размер одного сообщения также ограничены; при превышении мод отключается.
- Команды сущности разрешены только сущностям namespace вызывающего мода. Нельзя управлять сущностями другого мода.

Пример обработки ошибки запроса:

```python
def spawn_failed(error):
    api.log(f"Не удалось создать сущность: {error['message']}")

api.spawn_entity('wolves:wolf', 10, 12, on_error=spawn_failed)
```

## Предметы и сущности

Манифест может объявлять определения в массивах `items`, `entities` и `recipes`. ID каждого определения обязан использовать namespace мода. У предмета можно указать `title`, матрицу `icon` (до 32×32) и описание снаряда `projectile` (`ammo`, скорость 5–30, урон 1–10, cooldown 0.2–5 секунд). Рецепт задаётся полями `ingredients` (объект ID предмета → количество), namespaced `result` и `count` (1–64); он появляется в обычной сетке крафта 2×2, если точный набор ингредиентов помещается в сетку. У сущности доступны `health`, `speed`, `height`, `radius`, `damage`, список до 48 цветных кубов `model`, список `loot` и `tame_item`. Части модели задаются через `name`, `x/y/z`, `sx/sy/sz`, `color`; `tamed_only: true` скрывает часть до приручения.

Лучник, приручаемый волк и курица в `mods/archery_wolves/mod.json` показывают эти определения: скелет появляется только ночью, стреляет, а после смерти роняет кость, лук и стрелы; курица появляется днём и роняет курятину и перья. Волк появляется и днём, днём не нападает, приручается костью при использовании по нему. Приручённый волк следует за игроком и атакует цель, которая ударила хозяина или которую ударил хозяин. Мод задаёт рецепт стрел: одна палка и одно перо дают 10 стрел. `mods/minimap/` показывает terrain-сетку и маркеры сущностей через `world.surface` и `ui.image`; нажмите `M`, затем ЛКМ по карте, чтобы поставить сохранённую метку, или ПКМ рядом с меткой, чтобы удалить её.

## Безопасность

Моды запускаются отдельными процессами, а игровой мир доступен через ограниченный JSON-RPC API, не через Java-объекты. Но Python-процесс **не является песочницей**: он работает с правами пользователя и потенциально может читать/изменять доступные пользователю файлы или запускать процессы. Запускайте только доверенные моды.
