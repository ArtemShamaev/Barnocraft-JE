# Barnocraft Java Edition — jMonkeyEngine

Настольная игра на **Java 17+ / jMonkeyEngine 3.8.1-stable / LWJGL 3**. Исходный `main.html` сохранён для сравнения; игра запускается на Java, браузер не нужен. Текстуры из `src/imgs` включаются в JAR при сборке.

## Сборка и запуск

Нужны JDK 17+, Maven 3.9+ и графическое окружение с OpenGL 3.2+. Первая сборка требует доступа к Maven Central.

```sh
mvn package
java -jar target/barnocraft.jar
```

Готовый JAR содержит движок, текстуры и нативные библиотеки. Для его запуска достаточно Java. На macOS:

```sh
java -XstartOnFirstThread -jar target/barnocraft.jar
```

В Windows запускайте `run.bat`. Он через `run.ps1` ищет Java 17+ в `JAVA_HOME`, `PATH` и стандартных каталогах установки. Ошибка с версиями классов `61.0` и `52.0` означает, что команда `java` запускает Java 8, даже если Java 17 уже установлена. Проверьте `where java` и `java -version`. При необходимости задайте `set "JAVA_HOME=C:\Program Files\Java\jdk-17"` (укажите свой каталог) и запустите `run.bat`. Прямой вызов `java -jar` использует Java из `PATH`.

При разработке можно использовать `mvn compile exec:java`. Зависимости кэшируются в `.mvn/repository`; после первой сборки доступно `mvn -o package`.

## Измерение «Адский лес»

В мире появляются природные структуры **Портал**: тёмная каменная рама с золотыми знаками, фиолетовое поле и жар-кристаллы у входа. Первый портал находится неподалёку от начальной точки появления; остальные разбросаны по миру. Чтобы найти ближайший портал, нажмите **F3**, введите `tp portal` и нажмите **Enter**. Команда переносит на площадку перед порталом в текущем измерении; в мультиплеере она доступна хозяину сервера. Чтобы перейти, войдите в фиолетовое поле. В Адском лесу вас встретит парный портал, через который можно вернуться. После перехода действует короткая защита от случайного немедленного возврата.

Портал нельзя скрафтить, получить как предмет, поставить в креативе или разобрать. Камни его основания добываются, сама рама и поле защищены. Выход при переходе освобождается, чтобы игрок не застрял в чужой постройке.

Адский лес — отдельный вулканический мир под базальтовым сводом: багровые рощи, лавовые низины, красный туман и светящиеся кристаллы. Первый выход расположен в сухой роще. Лава наносит урон в выживании.

Новые добываемые и устанавливаемые блоки: **пепельная почва, адский камень, базальт, багровый ствол, багровая листва, жар-кристалл**. Естественные блоки: **лава, рама портала, поле портала**. Девять PNG находятся в `src/imgs`; оба варианта текстур используют эти изображения. [Описание и промпты текстур](docs/hell-forest-textures.md).

Новые мобы:

- **Лесной бес** — парит над землёй, преследует игрока и атакует вблизи; оставляет жар-кристаллы.
- **Пепельный кабан** — тяжёлый рогатый зверь, бросается на ближайшего игрока; оставляет уголь.

В Адском лесу одновременно живут не более четырёх мобов. Попытка появления одного нового моба происходит раз в 25 секунд, не ближе 24 блоков от игроков и 20 блоков от порталов. Далёкие мобы (дальше 80 блоков от всех игроков) исчезают. Лимит применяется и к старым сохранениям.

Инвентарь переносится между измерениями. Постройки и существа сохраняются отдельно: основной `world-N.dat` хранит текущее положение хозяина, файлы `world-N-surface.dat` и `world-N-hell_forest.dat` — оба измерения. При переносе сохранения копируйте все три файла. Удаление мира через меню удаляет и его измерения. Старые сохранения открываются как обычный мир.

В мультиплеере игроки могут находиться в разных измерениях: портал переносит только вошедшего игрока. Блоки, мобы и персонажи синхронизируются с учётом измерения. Для этой версии необходимо обновить JAR у всех участников.

Проверка перехода в обе стороны, мобов, сохранения и повторной загрузки: `java -jar target/barnocraft.jar --hell-smoke`. Тест использует временный мир; снимки — `target/hell-smoke-*.png`.

## Мультиплеер в локальной сети

До восьми игроков вместе с хозяином. На обоих компьютерах нужна одна и та же сборка JAR.

1. Хозяин открывает обычный мир через **Миры**, нажимает **Esc → Открыть для сети**, выбирает **Саню** или **Ваню** и TCP-порт (1–65535, по умолчанию 25565), затем **Открыть мир**.
2. В меню паузы появится LAN-адрес и порт. Например, `192.168.1.21:8088`.
3. Другой игрок выбирает **Мультиплеер** в главном меню, вводит **Адрес: 192.168.1.21**, **Порт: 8088**, выбирает персонажа и нажимает **Подключиться**. Адрес и порт — отдельные поля. Tab переключает поле, Backspace удаляет символ, Delete очищает поле, Enter подключает.
4. Хозяин должен оставить мир открытым. Меню паузы и потеря фокуса не останавливают сервер. **Закрыть сеть**, выход в главное меню или закрытие игры отключают гостей.

Саня носит синюю футболку с полосой, Ваня — красную рубашку и бороду. Модели поворачивают голову, двигают руками и ногами при ходьбе, принимают позу прыжка и проигрывают взмах руки. Выбор облика не ограничивает число игроков: один облик могут выбрать несколько человек.

Мир, блоки, двери, вода, существа и общие контейнеры синхронизируются через хозяина. Изменения мира сохраняются в его обычный слот; клиент не перезаписывает свои миры. Инвентарь гостя действует в пределах подключения и пока не сохраняется между сеансами. Это кооперативный LAN-режим без учётных записей и PvP; поведение Python-модов, рассчитанных на одного игрока, не гарантируется для гостей.

### Если соединение не устанавливается

- Для второго компьютера нужен адрес Wi-Fi/Ethernet хозяина, а не `localhost`, адрес Docker или VPN. `127.0.0.1` работает только между окнами на одном компьютере.
- Указанный порт должен совпадать у хозяина и гостя. В Linux команда `ss -ltn` должна показывать выбранный порт после **Открыть мир**. Слушатель принимает подключения на всех IPv4-интерфейсах.
- Если подключения на этом компьютере работают, а с другого устройства — нет, проверьте разрешение входящего TCP-порта в межсетевом экране и отсутствие изоляции клиентов Wi-Fi/гостевой сети. Для одной локальной сети переадресация порта на роутере не нужна.
- После обновления полностью перезапустите игру **на обоих компьютерах** с новым JAR. Разные версии сетевого протокола теперь показывают явную ошибку.
- Проверка связи работает в сетевых потоках независимо от загрузки/отрисовки. Устаревшие позиции и снимки мира заменяются свежими и не переполняют очередь. Начальная передача мира ожидается до 90 секунд. Причины отказов сервера выводятся клиенту и в консоль с меткой `[LAN]`.

Проверки: `mvn test`; два настоящих игровых окна — `python3 tools/network_smoke.py` после `mvn package`. В Linux без монитора: `env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 xvfb-run -a python3 tools/network_smoke.py`. Для проверки конкретного интерфейса и порта добавьте `--address 192.168.1.21 --port 8088`. Используются временные миры; снимки и журналы — `target/network-*`.

## Меню и сохранения

Игра открывается в главном меню:

- **Мультиплеер** — подключение по адресу и порту, выбор Сани или Вани.
- **Миры** — кнопки **Мир 1**, **Мир 2**, **Мир 3**, **Мир 4**, **Мир 5**. Пустой слот создаёт новый случайный мир; существующий загружает сохранение.
- **Настройки** — дальность прорисовки (2–6 чанков в каждую сторону), чувствительность мыши и угол обзора. Нажатие на параметр циклически меняет его значение. Настройки применяются сразу и сохраняются.
- **Выход** — закрыть игру.

`Esc` открывает паузу с продолжением игры, настройками, ручным сохранением, возвратом в главное меню и выходом. Потеря фокуса также включает паузу.

Пять независимых файлов расположены в `saves/world-1.dat` … `saves/world-5.dat` относительно рабочей папки запуска. Сохраняются seed мира, изменённые блоки, двери с ориентацией и открытым/закрытым состоянием, повороты блоков и ступенек, позиция игрока, направление взгляда и выбранный слот хотбара. Неизменённая местность восстанавливается по seed.

Автосохранение выполняется каждые 30 секунд игры, при включении паузы, возврате в главное меню и штатном закрытии окна/F10. Файл сначала записывается во временный файл, затем заменяет сохранение (атомарно, если файловая система поддерживает). При ошибке записи появляется сообщение; выход отменяется, чтобы дать возможность повторить сохранение. Повреждённый слот не заменяется новым миром автоматически.

Настройки хранятся в `saves/settings.properties`. Можно явно выбрать каталог данных:

```sh
java -Dbarnocraft.saves=/путь/к/сохранениям -jar target/barnocraft.jar
```

## Мир и загрузка чанков

Размер мира — **1000 чанков всего**, сетка **40 × 25**. Чанк занимает 16 × 16 блоков по горизонтали и все 32 блока высоты. Полный размер мира: **640 × 32 × 400 блоков**.

Мир не создаёт всю геометрию при запуске. Ближайшие чанки строятся в фоновом потоке, в порядке расстояния от игрока; за кадр подключается не более одного готового чанка. Дальние чанки удаляются из сцены по мере перемещения. При первоначальной загрузке игра ждёт ближайшую область 3 × 3. Если игрок достиг ещё не готовой области, движение временно ожидает её загрузки, чтобы не провалиться в невидимую местность.

По умолчанию радиус прорисовки — 3 чанка, то есть до 49 чанков в сцене; максимальная настройка 6 — до 169. Туман соответствует выбранному расстоянию. Воксельные данные генерируются по запросу регионами 80 × 80 блоков; кэш ограничен восемью регионами. Изменения игрока хранятся отдельно от кэша и не теряются при выгрузке. Соседние чанки обновляются при изменении блока на стыке.

Сохраняются холмы, впадины, деревья, пещеры с входами с поверхности, уголь, железо и участки глубинной породы `deeprock.png`. Рельеф непрерывен на стыках чанков и регионов. Пещерные системы генерируются внутри отдельных регионов. Стартовая поляна свободна от деревьев, основание под ней не вырезается пещерами.

## Управление, дверь и ступеньки

| Действие | Управление |
| --- | --- |
| Выбрать кнопку меню | ЛКМ |
| Двигаться / смотреть | WASD / мышь |
| Прыгать | Space |
| Разрушить блок | ЛКМ |
| Поставить выбранный блок | ПКМ |
| Выбрать блок или инструмент | 1–9 / колесо мыши |
| Выбрать бревно / дверь | 6 / 7 |
| Выбрать ступеньки / поворачиватель | 8 / 9 |
| Повернуть блок на 90° | ПКМ с выбранным поворачивателем |
| Открыть или закрыть дверь | ПКМ по двери |
| Пауза / продолжить | Esc |
| Сохранить и выйти | F10 / закрыть окно |

Дальность взаимодействия — **5 блоков**. В хотбаре: дёрн, камень, песок, доски, стекло, бревно, дверь, ступеньки и поворачиватель.

Дверь использует `door.png`, имеет ширину **1 блок** и высоту **2 блока**. Для установки нужны опора и две свободные клетки. Ориентация зависит от направления взгляда. ПКМ по любой половине двери переключает её состояние если не выбран поворачиватель. Створка поворачивается на 90°; столкновения и выбор лучом учитывают её тонкую форму, поэтому через открытый проём можно пройти. Дверь не закрывается сквозь игрока. Разрушение любой половины или опоры удаляет дверь целиком.

Ступеньки занимают одну клетку 1 × 1 × 1 и состоят из двух ступеней высотой по полблока. На них можно подниматься и спускаться без прыжка. При установке подъём направлен от игрока; форма, столкновения, выделение и выбор лучом учитывают четыре ориентации. Полные блоки автоматически не преодолеваются, низкий потолок не позволяет подняться.

**Поворачиватель** — инструмент в слоте 9, не устанавливаемый блок. ПКМ поворачивает выбранный блок на 90° вокруг вертикальной оси в пределах обычной досягаемости 5 блоков. Ступеньки меняют направление подъёма, дверь поворачивается целиком с сохранением открытого/закрытого состояния, у кубов поворачиваются текстуры. Четыре поворота возвращают исходное состояние; у симметричной текстуры изменение может быть малозаметно. Поворот двери или ступенек сквозь игрока запрещён. ЛКМ сохраняет обычное разрушение блока.

Повороты сохраняются во всех пяти мирах. Формат сохранения обновлён до версии 2; файлы версии 1 читаются с исходной ориентацией блоков и при следующем сохранении обновляются без изменения seed и построек.

Текстуры `src/imgs/stairs.png` и `src/imgs/rotator.png` созданы встроенным `image_gen`. [Точные промпты и описание файлов](docs/generated-textures.md).

## Баланс руд

| Руда | Шанс начала залежи* | Целевой размер | Минимальная глубина под поверхностью |
| --- | --- | --- | --- |
| Уголь | 2% | 3–6 блоков | 2 блока |
| Железо | 1,6% | 3–6 блоков | 4 блока |

*Шанс применяется к свободному блоку породы у полости пещеры, при достаточной глубине. Это не процент всех блоков мира. Залежи могут объединяться или быть меньше у края породы. Железа примерно на 44% меньше предыдущей настройки на контрольной выборке из 20 участков; уголь по-прежнему чаще. Параметры — в `Underground.java`.

## Проверки

```sh
mvn test
java -jar target/barnocraft.jar --smoke
```

Автоматические тесты проверяют генерацию, руды, физику, геометрию, лучевой выбор, двухблочные двери, прохождение через открытый проём, сохранения всех пяти слотов, настройки, повреждённые файлы, генерацию по запросу и сохранность изменений после вытеснения из кэша, подъём по ступенькам во всех четырёх направлениях, поворот блоков, сохранение ориентаций и совместимость старых сохранений.

`--smoke` проверяет настоящее окно OpenGL: главное меню, настройки, пять кнопок миров, открытие двери по ПКМ, установку ступенек из слота 8 и поворот инструментом из слота 9, переключение миров и восстановление двери и ступенек, загрузку удалённой области и выгрузку прежних чанков. Используются отдельные временные сохранения в `target/smoke-saves-*`; обычные миры не затрагиваются. Снимки — `target/menu-smoke-1.png` … `target/menu-smoke-8.png`. Успех обозначается `BARN0CRAFT_SMOKE_OK`, после чего окно закрывается. Запускайте из корня собранного проекта.

Linux CI с Xvfb и Mesa:

```sh
env -u WAYLAND_DISPLAY XDG_SESSION_TYPE=x11 xvfb-run -a java -jar target/barnocraft.jar --smoke
```

Проверено на Java 21 / Linux / Mesa llvmpipe. Windows и macOS отдельно не проверялись. Звук и многопользовательский режим отсутствуют. Сложные перекрытия стекла могут давать артефакты сортировки прозрачности.

## Код

Исходники находятся в `src/main/java/com/barnocraft`:

- `Barnocraft` — экраны, управление, жизненный цикл и автосохранение.
- `Menu`, `Hud`, `GameOptions` — кнопки, интерфейс и настройки.
- `World`, `Region`, `Terrain`, `Underground` — кэш данных, изменения, рельеф, пещеры и руды.
- `SaveStore` — формат и безопасная запись пяти слотов.
- `Door`, `Stairs`, `Player` — форма двери, столкновения и физика.
- `ChunkMesh`, `WorldView` — меши и фоновая загрузка чанков.

Версия сохранения относится и к формату файла, и к алгоритму генерации: при изменении генератора требуется продумать совместимость существующих миров.

## День, ночь и выживание

Полные сутки занимают 20 минут игрового времени. Освещение, небо и туман плавно меняются; в паузе время останавливается. Ночью рядом с игроком появляются зомби (не более 24). Они преследуют игрока и снимают 2 единицы здоровья за удар с интервалом в секунду. Стены и перекрытия защищают от ударов. ЛКМ атакует зомби; три попадания убивают его и оставляют гнилую плоть.

Здоровье отображается в левом верхнем углу: максимум 20. После смерти игрок возрождается с полным здоровьем, а предметы выпадают, если не включено сохранение инвентаря. Время суток, здоровье и зомби записываются вместе с миром (формат 13); старые сохранения загружаются с начальными значениями для отсутствующих данных.

### Свет и выживание

ПКМ с бараниной восстанавливает 3 единицы здоровья (максимум 20); при полном здоровье еда не расходуется. Падение более чем на 3 блока наносит урон при приземлении. После удара овцы несколько секунд бегут от игрока и ищут обход препятствий.

Пещерные тоннели постепенно спускаются к нижним слоям. Факел светит в руке, а для установки используется фонарь (факел + стекло + железный слиток). Фонарь излучает свет уровня 14. Ночью появляется не более одного зомби в минуту, максимум три; в пределах 12 блоков от фонаря новые зомби не появляются. Кровать (две шерсти + две доски) занимает два блока и позволяет пропустить ночь по ПКМ, если рядом нет зомби.

### Время суток и вода

В консоли: `time set day` — день, `time set night` — ночь. Допускается начальный `/`. После команды цикл суток продолжается; установленное время сохраняется вместе с миром.

В низинах генерируются прозрачные водоёмы с песчаным дном. Через воду видны дно и подводные блоки; на открытых краях и водопадах рисуются боковые грани. В воде движение замедляется; удерживайте пробел, чтобы всплывать. Вода смягчает падение, а под поверхностью видимость ограничивает синий туман. `give water 64` выдаёт водяные блоки для размещения по ПКМ. Можно строить в воде; прицел проходит сквозь неё к твёрдым блокам. Вода падает и растекается по опоре; механики утопления нет.

Золото встречается в пещерах на глубине от 8 блоков. Печь превращает руду в слитки; камнерез делает золотое навершие за 5 слитков и 1 уголь. Навершие с палкой даёт золотой инструмент. Один золотой слиток в крафте даёт поворачиватель: ПКМ поворачивает выбранный блок на 90°.

### Небо и освещение

Процедурное небо показывает солнце, луну, звёзды и движущиеся облака. Рассвет и закат меняют цвет горизонта, дымки и освещения блоков; цикл использует время сохранённого мира. Сундук имеет непрозрачную деревянную текстуру, а его внешние грани получают освещение соседних ячеек.

### Креатив и кубический шрифт

Название игры — **Barnocraft Java Edition**. Структура проекта и команда запуска прежние: `java -jar target/barnocraft.jar`.

Нажмите **F3**, введите `gamemode 1`, затем **Enter**: включится креатив с полётом, неуязвимостью, бесконечными блоками и мгновенным разрушением. **Пробел** — лететь вверх, **левый Shift** — вниз, **WASD** — движение. **E** открывает каталог: выберите слот быстрой панели, затем предмет; стрелки переключают страницы. Наведение показывает название предмета. `gamemode 0` возвращает выживание; предметы панели остаются, снова действуют гравитация, голод, урон и расход ресурсов. Режим сохраняется отдельно в каждом мире; старые сохранения открываются в выживании.

Весь текст Java-интерфейса использует собственный растровый шрифт Barnocraft: кубические прописные формы, кириллица (включая Ё), латиница, цифры и символы интерфейса, без сглаживания и зависимости от системных шрифтов.

Проверка креатива и интерфейса: `java -jar target/barnocraft.jar --creative-smoke`. Использует временный мир, снимки — `target/creative-smoke-*.png`.

### Панорама загрузки и вода

Экран загрузки показывает отдельную панораму: лес и пустыню, ступенчатый стенд блоков, овцу, зомби и реку с плавающими рыбами. Камера плавно движется; сцена не записывается в игровой мир.

Вода падает вниз и растекается по опоре на несколько блоков, учитывает стены и постепенно высыхает после удаления источника. У потока меняется уровень поверхности, видны боковые грани водопадов. В воде игрок движется медленнее; удерживайте **Пробел**, чтобы плыть вверх. **ПКМ с ведром** набирает или выливает воду. Источники и уровни потока сохраняются с миром. Это простая блочная симуляция, без расчёта давления или сохранения объёма жидкости.

Моды загружаются из корневой `mods` рядом с проектом, в том числе при запуске из `target`; `target/mods` не используется. Явный путь по-прежнему задаётся через `-Dbarnocraft.mods=/путь/к/mods`.

Проверка сцены и воды: `java -jar target/barnocraft.jar --panorama-smoke`; снимки — `target/panorama-smoke-*.png`.
